Design notes

Event has two FKs

project_id is denormalized on Event intentionally. Without it, querying all events for a project requires joining through Issue every time — an extra join on a high-volume table.

first_seen vs last_seen

first_seen is set once on Issue creation and never updated. last_seen is updated every time a new Event arrives with the same fingerprint.

last_triggered_at is nullable

Starts as NULL — meaning the alert has never fired. The Celery Beat checker treats NULL as always eligible. Set to now() after firing to enforce the cooldown window.

occurrences uses F() expressions

Increment with F('occurrences') + 1 not issue.occurrences += 1 — avoids race conditions when multiple Celery workers process events simultaneously.

api_key auto-generated

Generated via uuid.uuid4() on Project.save() if not already set. Never exposed in list endpoints — only shown once on project creation.

fingerprint unique per project

The unique constraint is on (project, fingerprint) together — not just fingerprint alone. Same error in two different projects should create two separate Issues.
